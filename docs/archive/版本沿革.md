# dungeonPOE 版本沿革（封存）

從舊 `CLAUDE.md` 開頭搬來，照原文；現行規則在 `CLAUDE.md`。

**最高優先：任何改動都先讀 `docs/設計原則.md`**（MDA 從樂趣倒推機制、隨機性規則、從《塞令老師》學到的教訓），規則與數值在 `docs/企劃書.md`，改了要同步。

**每次新對話開始**：先用 Skill 啟動 `ponytail`（最小完整改動）、`grilling`（先把計畫問清楚再動手）和 `ambition`（動手前把目標拉高、拉深、拉廣，更大的版本當選項提給使用者）。

**只要動到 UI／UX：一定先啟動 skill `ui-design`**（長相照 `DESIGN.md`；動到互動、動畫、手勢才加 `apple-design`／`animate`；技術限制與測試尺寸照 `docs/介面規範.md`）。0.3.0 起是**掛機打寶**（角色自動戰鬥，規則在 `docs/企劃書.md` 2.1），**平台優先順序分階段：M0–M1 手機直立 390×844 優先；M2 起 390×844 與桌機 1280×720 同級。詳見 `docs/production/gdd.md`**；操作規則與對照表在第 9 節「操作模式」，**改介面各尺寸都要做、都要測**——手機直立 390×844 與 375×667（優先）、手機橫向 844×390 與 667×375、桌機 1440×900 與 1280×720（面板不能超出畫面）（`node tools/touch_check.js 寬 高`，要先開本機伺服器；0.2.14 起手機有直立／橫向兩種操作，設定裡選，`S.orient`、`PORT()`）。遊戲邏輯只透過 `mouseWorld()` 與移動方向拿輸入（AI 也是：`AI.on` 時兩者讀 `AI.aim`、`AI.mv`），不要在技能、戰鬥程式裡判斷是不是手機或自動。

## 舊溝通規則裡的歷史（原文）
- 版本號：0.2.x。改版本時改 `js/data.js` 的 `VER`、`index.html` 所有 `?v=` 和 `version.json`（手機拿到快取的舊頁面時，`main.js` 的 `verCheck` 看它不同就換網址重新載入），再更新 `CHANGELOG.md`。
- 流程：先改、先測，確認 OK 後再 commit + push（push 前先問使用者）。
- 獨立 repo（https://github.com/Shiroyashatw/dpoe ）；0.2.75 以前在《塞令老師》repo（`Shiroyashatw/wayfarer`）的 `dpoe/` 子資料夾，歷史已一起搬過來。不要再去讀 wayfarer 的檔案。

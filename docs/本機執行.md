## 本機執行

python3 -m http.server 8000   # 在 dpoe/ 底下，開 http://localhost:8000

## 每版 AI 試玩報告（M2-10）
每個改了 `VER` 的 PR 都附 A1–A10 指標表（門檻在 `docs/production/specs/M2-03-addictiveness-criteria.md`）：
```bash
python3 -m http.server 8000 &
node tools/ai_report.js evidence/<代號>
```
- 五個尺寸同時跑 `tools/camp_run.js`（遊戲內時間）：390×844、1280×720 各 120 分鐘（A5 要無人 2 小時），375×667、844×390、1440×900 各 30 分鐘；這台雲端機器 4 核約 2 小時。
- 產出 `evidence/<代號>/A1-A10.md`（總表：每格是否達標＋量測值；後面自動接 M2-03 完成標準與上一版比對），各尺寸另有 `.md`（含 30 分鐘表、資源曲線、決策紀錄）、`.json`、`.log` 與第 30／120 分截圖。把 `A1-A10.md` 整份貼進 PR 說明。
- 某個尺寸失敗（`.log` 看原因）就再跑一次同一個指令：同一個 commit 已有 JSON 的尺寸不重跑。
- 自動比對（`tools/ai_compare.js`，`ai_report.js` 跑完自己叫）：先列 M2-03 完成標準（卡關 A2 ≤ 5 分鐘、30 分鐘新東西 A3 ≥ 10；390×844 與 1280×720 都過才算達標，其他尺寸參考），再逐格比上一版（✅→❌ 標**退步**，A2 附秒數差、A3 附個數差）。上一版＝`evidence/` 裡其他有 `A1-A10.md`、commit 最新的資料夾；要指定就加 `--base=evidence/<代號>`。只想重比不重跑：`node tools/ai_compare.js evidence/<本版> [evidence/<基準>]`（寫 `比對.md`）；工具自我檢查 `node tools/ai_compare.js --test`。
- 未達標照實寫成發現，不要為了表好看改數值；比上一版退步的要在 PR 說明講。

## 需要 Grok 幫忙的時後（本機 Claude Code 用）

1. 取一個代號，把要 Grok 做的步驟、停在哪一步，寫進 ~/claude-runs/<代號>.prompt。
2. 寫 ~/claude-runs/<代號>.json，內容是 {"kind":"request_to_assistant","result":"<同樣的步驟>"}。
3. 用 Webhook 網址和金鑰 POST {"source":"claude-code","event":"run_done","name":"<代號>"}。
4. 等 ~/claude-runs/<代號>.reply 出現，讀完再自己打開頁面核對結果。

## 需要 Grok 幫忙的時後（雲端 Claude Code 用）

雲端機器上沒有 ~/claude-runs/，也送不出 Webhook，改用 GitHub 留言：

1. 取一個代號（只用英數、-、_）。
2. 有對應 PR：用 `gh api repos/Shiroyashatw/dpoe/issues/<PR 編號>/comments -f body=...` 留言，第一行寫「Grok 請求：<代號>」，下面寫要 Grok 做的步驟、停在哪一步。
3. 沒有對應 PR：開一個 issue，標題「Grok 請求：<代號>」，內文寫步驟和停在哪一步，並指派給 Shiroyashatw（`gh api repos/Shiroyashatw/dpoe/issues -f title=... -f body=... -f "assignees[]=Shiroyashatw"`）。指派才會叫醒 Grok。
4. 等同一個 PR 或 issue 出現開頭為「Grok 回覆：<代號>」的留言（用 `gh api .../comments` 定時讀），讀完再自己打開頁面核對結果。

# dungeonPOE 介面規範

改介面（畫面、面板、HUD、互動、動畫、說明文字的排版、CSS）時照這份。長相與「看不看得懂」照 `DESIGN.md`（一秒測試、版面原則、預算；數值跟 `DESIGN.md` 不一致時改這份），互動手感照 `apple-design`；這份提供 dungeonPOE 實際在用的數值、元件、技術限制與測試尺寸（兩個 skill 都不能推翻）；操作規則在 `docs/企劃書.md` 第 9 節。（舊的《塞令老師》直式規範在 `封存/設計規範.md`，不適用。）

## 1. 平台與測試尺寸

- **手機直立為主、桌機跟著**（0.3.0 掛機；0.2 是桌機為主）。手機是全螢幕（`body.touch`），直立或橫向看設定 `S.orient`。
- 每次改介面，六個尺寸都要截圖（直立優先）：
  - 手機直立 **390×844**、**375×667**，手機橫向 **844×390**、**667×375**
  - 桌機 **1440×900**、**1280×720**（面板不能超出畫面）。
  - 手機的測試（`node tools/touch_check.js 寬 高 [網址]`，要先開本機伺服器；直的尺寸自動測直立操作；瀏覽器模擬時寬度小於 768 才會切成手機模式）。直立是 `body.touch.port`（`PORT()`，設定裡選，`S.orient`）。
- 遊戲邏輯只透過 `mouseWorld()` 與移動方向拿輸入，技能、戰鬥程式裡不判斷是不是手機。

## 4. 互動與動畫

- **按下就有回饋**：可點的元件 `:active` 縮小（`transform: scale(0.95～0.97)`）。
- **放開才執行**：手機的互動鍵、點地上的擺設都等手指放開（`click`）才開面板；按下就開的話，放開的那一下會落到剛長出來的按鈕上。
- **點出來的說明框變高時**（`#tip.act`）：框裡可以捲，動作鈕（`.tqa`）黏在底部、永遠按得到。
- 面板出現：`pop`（置中面板）、`inL`／`inR`（左右面板），200ms、`cubic-bezier(0.23, 1, 0.32, 1)`；動畫不擋操作。
- **減少動態**：`@media (prefers-reduced-motion: reduce)` 只淡入淡出。
- 不靠 hover 傳達資訊（手機沒有 hover）：不能按的按鈕把原因寫在按鈕上。桌機可以用滑過加速（昇華盤面），但手機要有對應的點選。
- - 不用 `backdrop-filter` 或大面積模糊（效能）。
- 世界地圖：拖曳 1:1 跟手，放開照放開前一刻的速度滑（停住才放開就不滑），鏡頭出界軟彈回；世界展開碰一下就結束；減少動態時沒有慣性、環境動畫與演出。
- 戰鬥特效用 pixelfx 序列圖（`fxs()`，`js/fxsheets.js`）；遊戲畫面上的東西畫在 canvas，不做成 DOM。

## 5. 資訊量

- 清單只放圖示＋名稱＋一行說明；詳細的放說明框。
- 數量 0、不能用、還沒開放的收起來或標 `.lock` 並說明原因。
- 能用數字或顏色代替句子就不要寫句子（▲▼、框色、星級）。

## 6. 檢查

- 改完在第 1 節的六個尺寸截圖，看：面板沒有超出畫面、主要按鈕看得到、字不小於 10px、按鈕不重疊。

## 7. 文字重點（0.2.75，先套在技能面板；其他面板留收尾）

說明文字不是一整團灰字：讀的人要一眼找到「數字」「會改玩法的名詞」「代價」。技能面板的文字由 `skpanel.js` 的 `rich()` 組出（數字、名詞、元素詞自動標），規則：

- **數字**一律 `--title` 白粗體等寶（`tabular-nums`，`.n`）；單位（%、秒、顆）不加粗。
- **會改變玩法的名詞**（異常、地面、標籤、機制名）用詞綴藍 `--affix: #9aa6ff`（`.kw`），並接現有的 `termify` 名詞卡（`.term`，點了出 `#ttip`）；同一段只有第一次是可以點的。
- **傷害類型與抗性**用元素色（`.res-fire`／`.res-cold`／`.res-light`／`.res-chaos`），只上那個詞，不上整句。
- **代價**用 `--dim`、不能用與失效用 `--bad`（0.4.8，`DESIGN.md` 第 4 節；`--warn` 只給地圖危險度）；增益比較用 `--good`；**覺醒**用覺醒紫 `--awk: #b592ff`（`--awk-bg: #1b1526`，跟昇華橘同層級，不佔稀有度與元素色）。
- **每段最多兩種強調色**；**每個面板只有一個放大的數字**（技能面板是「每秒」）。
- 說明寫給玩家看的事（這招做什麼、為什麼要它），不寫介面怎麼用；區塊沒內容就不出現（沒覺醒的招不畫覺醒區塊、沒追憶不畫追憶）。
- 按鈕裡不放可點的名詞（`button` 不能巢狀）：覺醒卡的說明用 `rich(text, true)`，名詞只上色不能點。

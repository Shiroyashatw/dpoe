# dungeonPOE 介面規範

改介面（畫面、面板、HUD、互動、動畫、說明文字的排版、CSS）時照這份。長相與「看不看得懂」照 `DESIGN.md`（一秒測試、版面原則、預算；數值跟 `DESIGN.md` 不一致時改這份），互動手感照 `apple-design`；這份提供 dungeonPOE 實際在用的 class、元件、技術限制與測試尺寸（兩個 skill 都不能推翻）。**外觀的數值（色、框、字級、元件尺寸、圖示尺寸）不在這裡重抄**：色值與 token 角色在 `docs/production/specs/M2-36-palette-tokens.md`，畫法在 `M2-36-drawing-rules.md`，元件與畫面在 `M2-33-index.md` 連到的各批（下稱 M2-33 F／2a／2b／3a／3b）；這份跟它們不一致時以規格為準。操作規則在 `docs/企劃書.md` 第 9 節。（舊的《塞令老師》直式規範在 `封存/設計規範.md`，不適用。）

## 1. 平台與測試尺寸

- **直立 390×844 與桌機 1280×720 同級**，兩個都驗過才算完成：直立也要放得進 375×667，桌機要能只用滑鼠玩（M2 起；詳見 `docs/production/README.md`）。手機是全螢幕（`body.touch`），直立或橫向看設定 `S.orient`。
- 每次改介面，六個尺寸都要截圖（390×844 與 1280×720 同級）：
  - 手機直立 **390×844**、**375×667**，手機橫向 **844×390**、**667×375**
  - 桌機 **1440×900**、**1280×720**（面板不能超出畫面）。
  - 手機的測試（`node tools/touch_check.js 寬 高 [網址]`，要先開本機伺服器；直的尺寸自動測直立操作；瀏覽器模擬時寬度小於 768 才會切成手機模式）。直立是 `body.touch.port`（`PORT()`，設定裡選，`S.orient`）。
- 遊戲邏輯只透過 `mouseWorld()` 與移動方向拿輸入，技能、戰鬥程式裡不判斷是不是手機。

## 2. 變數（`css/style.css` 開頭的 `:root`）

只用角色 token，不在 CSS 或 JS 寫色碼、字級（hex、`rgb()`／`rgba()` 字面值都不行）；半透明用三元組 token：`rgb(var(--scrim-rgb) / 0.6)`。canvas 用 `PAL.xxx`（`js/palette.js` 開機時從 `:root` 讀）。全部 token、值與量測在 `docs/production/specs/M2-36-palette-tokens.md`；token 收斂（M2-36a）合併前的舊名對照在 M2-36a token 角色清單（https://cursor.com/canvas/store-82cf5215-7bf0-49e1-b610-9b76fbf158ee/8690e401-7ab1-410e-aa55-477941e622cb ），舊名不要再新增用法。

## 4. 互動與動畫

- **按下就有回饋**：按鈕 `:active` 下移 1 px（`translateY(1px)`）並拿掉外下緣影子；分頁格換底色、不縮放（M2-33 F §5、§7）。
- **放開才執行**：手機的互動鍵、點地上的擺設都等手指放開（`click`）才開面板；按下就開的話，放開的那一下會落到剛長出來的按鈕上。
- **點出來的說明框變高時**（`#tip.act`）：框裡可以捲，動作鈕（`.tqa`）黏在底部、永遠按得到。
- 面板出現：`pop`（置中面板）、`inL`／`inR`（左右面板），200ms、`cubic-bezier(0.23, 1, 0.32, 1)`；動畫不擋操作。
- **減少動態**：`@media (prefers-reduced-motion: reduce)` 位移、縮放、滑入改成直接出現，只留 ≤ 120 ms 的透明度變化。
- 不靠 hover 傳達資訊（手機沒有 hover）：不能按的按鈕把原因寫在按鈕上。桌機可以用滑過加速（昇華盤面），但手機要有對應的點選。
- 不用 `backdrop-filter` 或大面積模糊（效能）。
- 世界地圖：拖曳 1:1 跟手，放開照放開前一刻的速度滑（停住才放開就不滑），鏡頭出界軟彈回；世界展開碰一下就結束；減少動態時沒有慣性、環境動畫與演出。
- 戰鬥特效用 pixelfx 序列圖（`fxs()`，`js/fxsheets.js`）；顏色與飽和面積上限照 M2-36 畫法規則 §6，招牌特效換 PixelLab 素材（`M2-36-pixellab-prompts.md`）。遊戲畫面上的東西畫在 canvas，不做成 DOM。

## 補充

- 字級下限：資訊 14px、面板內最小 12px（標籤）；HP／MP 條內數字 11px；跳數字的螢幕下限依種類（M2-33 F §2、3a §1）。
- `--panel` 不透明；直立半版用 `--sheet-bg`。視覺方向（廟宇古地圖＋C 的用色規則）見 `DESIGN.md` 第 4、5 節。
- 不能復原的高代價動作才用 `confirm2` 按兩次，文字要寫出代價：開孔花掉現有靈魂一半以上時、第一次覺醒、重置天賦、重置昇華。
- 手機直立（0.4.4）：道具只用點的、不拖曳（`dragStart` 的 `nodrag`）；面板是半版，主要動作黏在面板底部（賣出鈕、昇華的說明列）。
- 手機橫向：要決定的東西要在第一屏（`tools/touch_check.js` 有檢查）。背包與裝備欄分頁（`LAND()`）；技能面板（這一招：左圓環、右資訊）、世界地圖、昇華石碑都是左右兩欄。畫面矮於 480 時技能寶石佔滿，背包用標題列的按鈕切換（`swapOn()`）。
- 狀態圖示：`combat.js` 的 `STATE`。玩家在技能列上方（`#mech`，圖示＋秒數或層數），怪物在血條上方（`drawMobStates`）。
- 召喚物（0.2.52）：受傷時頭上有小血條（`render.js` 的 `drawWolf`，大小與畫法跟怪物的一樣，友方用 `--good`）；等復甦時玩家狀態列多一格「復甦」（秒數＋隻數）；被魔像嘲諷的怪頭上是嘲諷圖示。都沿用現有元件，沒有新的。圖騰與砲塔圖騰（0.2.53）受傷時頭上也是同一種小血條（`drawUnit`）。
- 蓄力條（0.2.54，`render.js` 的 `chargeBar`）：蓄力技能按住時畫在主角腳下，一段一格（14×4、間隔 2）；正在蓄的那格跟著時間長（`--tx-off`），滿一格變亮（`--border-hi`），剛滿的那一下與全滿是最亮的 `--tx-strong`。不用黃色（黃色只給稀有度），沒有位移動畫，減少動態時不用另外處理。
- 蓄力的手勢（0.2.54）：桌機按住那一格的鍵、放開出手；手機按下技能鍵就開始蓄（按下就有回饋，不等放開），拖曳＝手動瞄準，拖回按鈕上＝取消（瞄準線變紅，跟其他技能一樣）並退回魔力。

## 7. 文字重點（0.2.75，先套在技能面板；其他面板留收尾）

說明文字不是一整團灰字：讀的人要一眼找到「數字」「會改玩法的名詞」「代價」。技能面板的文字由 `skpanel.js` 的 `rich()` 組出（數字、名詞、元素詞自動標），規則：

- **數字**一律 `--tx-strong` 粗體等寬（`tabular-nums`，`.n`）；單位（%、秒、顆）不加粗。
- **會改變玩法的名詞**（異常、地面、標籤、機制名）用 `--affix`（`.kw`），並接現有的 `termify` 名詞卡（`.term`，點了出 `#ttip`）；同一段只有第一次是可以點的。
- **傷害類型與抗性**用 `--el-*`（`.res-fire`／`.res-cold`／`.res-light`／`.res-chaos`），只上那個詞，不上整句。
- **代價**用 `--tx-dim`、不能用與失效用 `--bad`、提醒用 `--warn`（`DESIGN.md` 第 4 節）；增益比較用 `--good`；**覺醒**用 `--awk`（底 `--awk-bg`，跟昇華 `--asc` 同層級，不佔稀有度與元素色）。
- **每段最多兩種強調色**；**每個面板只有一個放大的數字**（技能面板是「每秒」）。
- 說明寫給玩家看的事（這招做什麼、為什麼要它），不寫介面怎麼用；區塊沒內容就不出現（沒覺醒的招不畫覺醒區塊、沒追憶不畫追憶）。
- 按鈕裡不放可點的名詞（`button` 不能巢狀）：覺醒卡的說明用 `rich(text, true)`，名詞只上色不能點。

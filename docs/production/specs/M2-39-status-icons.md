## 1. 為什麼要重做

現行圖示跟狀態對不上，有三類問題（main，`combat.js` 的 `STATE`、`art.js` 的 `ail_*`）：

1. **最常見的異常在用技能／輔助寶石圖。** 點燃 `sup_sp_gfire`、流血 `sup_sp_bleed`、中毒 `sup_sp_poison`、冰緩 `sk_frostarrow`、冰凍 `sk_frostnova`、感電 `sk_arc`、暈眩／僵直／觸電 `sup_sp_stun`、凋零 `sup_sp_wither`、致盲 `sup_sp_ailx`、曝曬 `sk_elemweak`。戰鬥裡看到的是招式圖，不是狀態本身。
2. **`ic_ail` 三張圖集（25 格、各 32×32、間隔 1）多數沒接上常見狀態，接上的也常錯。** 例如 `ail_doom`（翻開的書）用在壓碎、`ail_empN`（號角）用在石化、`ail_chgN`（拳頭）用在虛弱、`ail_dmark`（骷髏圈）用在血漬、`ail_n_corrode` 同時給腐化之血和緩速藤蔓、`ail_slow`（沙漏）同時給完全跛行和超重、`ail_n_seal` 同時給兩個不同狀態。
3. **顯示尺寸不是整數倍。** 玩家狀態列 `.stc .ic` 26、怪物頭上約 22、桌機地面 20，違反 F §12（PNG 只准 16 或 32）。F §10 寫「尺寸在第 3 批戰鬥畫面定」，本檔定案。

## 4. 畫法（相對王印 §5.1 的差異）

- 優先 16 枚本批先交手繪 16×16；獨立 32 等挑完後按提示詞表生成（16 不是 32 直接縮小，32 用定稿 16 當 init 再重排）。在 32 定稿前，HUD 用 16 的整數 2 倍（合法）。
- 16：不留透明邊，外緣 1 px `--scene-void`，造型 ≤ 3 個主要形狀，光從左上。
- 角色色：減益主體用 `--bad` 或該元素 token（`--el-fire`／`--el-cold`／`--el-light`／`--el-chaos`／`--hp` 作暗血、`--mp` 作暗冰）；正面用 `--good`（奉獻地面的頂光）。玩家列已有 `.stc.bad` 紅框，怪物頭上沒有框，所以剪影本身要能分。
- **飽和度：** 王印「C* > 40 的像素 ≤ 不透明 35%」是為古銅色印面寫的。狀態圖示的主體就是元素／負向 token，這個上限改成：主體可用該角色 token，即使超過 35%；不准再加比該 token 更飽和的色；描邊與陰影只用 `--scene-void`、`--panel-inset`、`--panel`、`--border`、`--hp`、`--mp`。`--rar-chase` 橙色不准用在狀態圖示。
- §6 圖示棋盤：16 ≤ 6。材質雜點目標 ≤ 3%；冰緩雪花尖端約 5.5%，這個造型接受。
- 轉灰階後 16 枚推薦剪影都要分得出來。

檔名與接線：`art/icons/ailment/ail_<id>_16.png`（id＝`ign`、`bleed`、`poison`、`chill`、`frozen`、`shock`、`elc`、`stun`、`wither`、`blind`、`exp`、`curse`、`rage`、`wet`、`pin`、`cons`）。工程把優先 16 的手繪像素圖編成 PNG（最近鄰、token 值從 `M2-36-palette-tokens.md` 換），作為挑圖定稿與 32 的 init。佇列與獨立 32 的生成照 `specs/M2-39-pixellab-prompts.md`，在雲端跑，金鑰只讀環境變數，不准寫進 repo。

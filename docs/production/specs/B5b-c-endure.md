## 2. 新增腐化詞

```js
// data.js CORR 加第 7 條（佔位值，待 B 階段模擬）
c_endure: { n: '耐力球上限 +{}，減少 8% 攻擊速度', r: [1, 1], fx: v => ({ chg_e: v, as: -8 }) }
```

| 欄位 | 值 | 說明 |
|---|---|---|
| id | `c_endure` | 照 c_* 命名 |
| 正面 | 耐力球上限 +1（`chg_e: 1`，r [1, 1]） | mumi 定 +1；固定值，所以 r 上下限相同（滿值不標，見名詞表） |
| 代價 | 減少 8% 攻擊速度（`as: -8`）**佔位值，待 B 階段模擬** | 其他 6 條代價是 hpP、defP、ms、mpP、resA、ss，as 沒人用過；主題「重、慢、扛」；法術、召喚 build 不受影響，符合 data.js:7667 規則「代價要有可能不影響你的 build」，也不抵銷自己的正面 |
| 權重 | 跟其他一樣（平均抽） | 程式沒有權重；加了第 7 條後每條從 1/6 變 1/7：每次腐化抽到某一條 40% × 1/7 ≈ 5.7%（原 6.7%） |
| 部位 | 不限 | 跟其他 6 條一樣 |
| 顯示 ZH | 「耐力球上限 +1，減少 8% 攻擊速度」 | 照 cwText 規則 |
| 顯示 EN | "+1 to Maximum Endurance Charges, 8% reduced Attack Speed" | 提案 |

### 手算（為什麼 −8%）
- 其他代價的大小：最大生命 −10%、全域防禦 −15%、移動速度 −10%、最大魔力 −20%、全元素抗性 −10%、技能速度 −10%，都在「一個能力 10% 上下」。
- 正面是有條件的：要有耐力球來源（粉碎重擊、破陣者越戰越勇／招架）才有用，沒有來源等於 0；所以代價比 10% 小一點，取 8%。
- 有銅皮鐵骨（5%／顆）時，+1 顆＝滿球多 5% 更少擊中傷害：3 顆 15% → 4 顆 20%，有效生命 1/0.85＝1.176 → 1/0.80＝1.25，約 +6.3%。對照 c_heavy +2% 最大元素抗性：元素承受 25% → 23%，約 8% 更少元素傷害。同一級。
- 沒有來源的 build：正面 0、代價只打攻擊 build；跟 c_over（沒用精魂就只剩代價）一樣是「挑 build」的詞。

## 3. 災魘詞第 2 行（B5b 的複合詞）

```js
// B5b 集中表裡 c_endure 的第 2 行（佔位值，待 B 階段模擬）
cal: { n: '每顆耐力球使你承受 {}%更少擊中傷害', r: [2, 2], fx: v => ({ chgEDef: v }) }
```

- 顯示 ZH：第 1 行「耐力球上限 +1，減少 8% 攻擊速度」，第 2 行縮排「每顆耐力球使你承受 2%更少擊中傷害」（字串照 data.js:6707 現有寫法，「%更少」中間不空格）。EN："2% less Hit Damage taken per Endurance Charge"（提案）。
- 數值 2：**佔位值，待 B 階段模擬**。手算：P2 要求第 2 行 ≥ 腐化詞本身（p＝0.5、m＝0）。沒有銅皮鐵骨、4 顆：8% 更少擊中傷害，有效生命 +8.7%，約是正面 +6.3% 的 1.4 倍，落在「中～高」預算。
- **跟銅皮鐵骨會疊**：ST.chgEDef 是加總（銅皮鐵骨 5＋災魘 2＝7／顆），combat.js:2150 只乘一次，不會兩邊各算一次；但沒有上限。破陣者滿配（越戰越勇 +2、c_endure +1＝6 顆）：現在 5×5＝25% → 7×6＝42%，有效生命 1/0.75＝1.33 → 1/0.58＝1.72。這是 S-b 要看的最強組合。
- 建議加上限：combat.js:2150 改成 `d *= 1 - Math.min(CHG_E_DEF_CAP, ST.chgEDef * chgN('e')) / 100`，`CHG_E_DEF_CAP = 60`（**佔位值，待 B 階段模擬**；現有最高 25%，不影響現況）。理由：以後再有來源可能 ≥100%，結果是負傷害。

## 1. 像素格與縮放（照 repo 實測）
- 世界座標：一格 `TS` = 48 世界 px（game.js L443）。畫面縮放 `ZOOM`：桌機 1.35；直立 `IW/480`（390 寬 = 0.8125，375 寬 = 0.78）。`DPR` 上限 2（main.js L166）。
- 主角、藏身處的材質像素 = 1.35 世界 px（render.js `HSC`、hide_bake.js `TX`）。
- **新地磚 32×32 像素，一格 48 世界 px → 每個材質像素 1.5 世界 px**（比主角粗 11%，接受；地板比角色粗一點不會搶角色）。螢幕上：桌機 2.03 CSS px、390 直立 1.22 CSS px（×DPR 2 = 2.44 裝置 px）、375 直立 1.17 CSS px。
- **只能縮放一次**：地板區塊（biome.js `bakeChunk`）要用材質像素烘（8 格 × 32 = 256 px 一塊），畫到畫面時一次放大 1.5 × ZOOM × DPR；不可先在世界座標以 1.5 倍烘、再被 ZOOM 縮一次（兩次最近鄰，會出現 1／2 px 交錯的條紋）。
- 圖片類 UI（PNG）只能用原尺寸或整數倍顯示：16 → 16／32，32 → 32／64（DPR 2 時自然是 2 倍）。**不可顯示成 40、22、36 這種非整數倍**。所以追逐橫幅 `#chase .cbi .ic` 的 40 改成 32，置中在原本 56 的格子裡（M2-33 會寫進該元件規格）。
- `image-rendering: pixelated` 給所有 PNG 素材；canvas 畫素材時 `imageSmoothingEnabled = false`。只有暗層、光暈（render.js L519、biome.js L583）保留平滑，那是光不是素材。

## 2. 光、輪廓、明暗、抖色
- **光從左上來**（約 10–11 點鐘方向），介面、圖示、地磚的凹凸都照這個方向。場景裡的燈光照舊由程式的暗層和 `bGlow` 疊上去，不畫進地磚。
- **輪廓**
  - 地磚：不描邊（lineless），形狀只靠明暗。
  - 王印等 PNG 圖示：外緣 1 px 單色描邊，用 `--scene-void`；圖示內部不再描邊，只用明暗分區。描邊不准斷、不准有 2 px 粗的角。
  - 例外（UIUX 11/20 17:06）：戰鬥 HUD 光環小圖（10／12）與分頁單色遮罩（16）**不描** 1 px 暗色外緣（光環格底 `--panel-inset` 上描邊看不到、遮罩只能一色）；照 battle-hud v1.3 `assets-borrowed.md` #1、#2。
  - 特效：不描邊（黑邊疊在怪物上會髒，沿用特效提示詞的舊規則）。
  - 程式畫的框：1 CSS px 線。
- **明暗階數**：每種材質最多 3 階（暗／本色／亮）＋1 個高光點。地磚只用該地形的 4 個場景 token；圖示整張 ≤ 10 色（含描邊）。不要用柔和漸層。
- **不抖色**：地磚、圖示、框都不准用棋盤格（Bayer）抖色或雜點。原因：畫面縮放 0.6–1.35 不是整數，1 px 棋盤會閃、會出現波紋。地磚的「孤立像素」（上下左右都不同色）≤ 2%。藏身處底圖的抖色是舊烘圖，這輪不動。
- **不反鋸齒**：地磚完全不透明；圖示的 alpha 只能是 0 或 255；只有特效可以有半透明。邊緣不准出現介於兩個 token 之間的過渡色（PixelLab 回來的圖要先過色票檢查，見提示詞檔 §6）。

## 3. 地磚（場景）
- 每種地形只用自己的 `--scene-<地形>-edge／-ground／-mid／-light` 四色（temple、lava、tomb、ice；營地沿用 temple）。
- **地板一定要暗**，否則 (b) 面板對場景 ≥ 1.4:1 會掉。面板 L* 20.6、地面 L* 6.5，餘裕只有 0.02；所以：
  - 地板每張磚：`-ground` 是底色，`-edge` 5–35%（縫、裂、陰影），3×3 全是 `-edge` 的實心暗塊 ≤ 2%，`-mid` ≤ 3%（只給磨亮的邊角），`-light` 0%。`-edge` 下限只要 5%：硬塞到 25% 會變成大片暗斑和暗框。
  - 檢查：整張磚的平均相對亮度 ≤ `-ground` 的相對亮度 × 1.02。只用暗色做紋理，亮色當點綴。
- **牆**（bWalls：頂面＋前面，前面高 0.55 格 ≈ 18 材質像素）：`-light` 只給牆頂的左上受光緣，≤ 15%。
  - 牆頂：`-mid`＋`-light` ≤ 80%。牆頂一定要比 `-ground` 的地板亮一階，房間形狀才看得出來（直立 375 寬時更要緊），比 `-ground` 亮的只剩 `-mid`，所以它會是牆頂的底色。牆頂畫正上方看到的面，不畫側面山形、冰刺剪影或立體塊。
  - 牆面：每半張 `-mid`＋`-light` 5–60%，最下面最暗。
  - 牆只在場地四周，(d) 中明度褐色以遊戲截圖（`tools/comfort.py`）為準。
- 要能無縫拼：左右、上下接縫的色差不能比磚內相鄰像素大（數字在提示詞檔 §6）。
- 地上的擺設（香爐、墓碑、冰晶、岩漿池…）、地面細節 `bDecals` 這輪照現行程式畫，只換成 token 色；岩漿的發光縫改由光層畫，地磚本身不放飽和色（C* ≤ 20）。

## 4. 面板與框（程式畫，兩種尺寸同一套）
| 層 | 底 | 框 | 立體感 |
| --- | --- | --- | --- |
| 面板 | `--panel`（直立半版用 `--sheet-bg`） | 1 px `--border-mid`；四角各一個 2×2 `--border-cap` 角點；圓角 0 | 寬 ≥ 240 的面板，在框內 3 px 再畫一條 1 px `--border`（舊地圖的雙線邊） |
| 凸起（按鈕、卡片） | `--panel-raised` | 1 px `--border-ctl`（一定要有） | 內上緣 1 px `rgb(var(--hl-rgb) / 0.08)`；外下緣 2 px `rgb(var(--scrim-rgb) / 0.5)` |
| hover／選中列 | `--panel-raised-2` | 1 px `--border-hi`（一定要有） | 同上 |
| 主按鈕 | `--act`，hover `--act-hi` | 1 px `--border-ctl` | 同上；字 `--on-act` |
| 選中分頁、紙卡 | `--sel`／`--paper` | 無 | 字 `--sel-ink`；只給小面積 |
| 凹槽（格子、輸入框、條的空段） | `--panel-inset` | 1 px `--border` | 內上緣 1 px `rgb(var(--scrim-rgb) / 0.5)`（凹下去的影子在上） |
| 場景上的字 | `--plate-world` | 無 | 字 `--tx-scene` |

- **凸起層的邊**：凸起層和面板只差 1.05–1.10:1，看不出來是正常的，**分層一律靠框和下緣影子**：凸起層 vs 自己的下緣影子 1.37:1、內上緣亮線 1.23:1，加上 `--border-ctl` 對面板 5.33:1。不准用把底色調亮來表現凸起。
- **Scrim 陰影（必做）**：凡是浮在場景上面的框（直立半版、桌機右欄、頂列、追逐橫幅、掛機卡、tooltip、對話框），框外加一圈 `box-shadow: 0 0 0 3px rgb(var(--scrim-rgb) / 0.6)`。理由：`--border-mid` 對場景亮部只有 1.75:1；加了之後，最不利的 lava／ice 亮部上也有 4.25:1（≥ 3）。桌機另外加柔影 `0 8px 24px rgb(var(--scrim-rgb) / 0.5)`；直立不加柔影（半版貼底，省效能）。框在面板裡面的（面板內的卡、格子）不加。
- 分隔線：1 px `--border`；列與列之間不畫線就用 8 px 間距。
- 進度條、生命／魔力條：照色票檔修正 1（不透明 `--panel-inset` 底、1 px `--border-mid`、平塗）。
- 不准：漸層底（現行 `linear-gradient(160deg, …)` 全拿掉）、木紋或紙紋貼圖、圓角 > 2、外發光、超過 1 px 的框（框角點除外）。

## 5. 圖示
### 5.1 PNG 圖示（王印，之後的狀態圖示照同一規則）
- 原生尺寸只有 32×32 和 16×16；16 不是 32 直接縮小，要重新整理（每個造型 ≤ 3 個主要形狀）。
- 32：留 1 px 透明邊（造型在 30×30 內）、外緣 1 px `--scene-void` 描邊、光從左上。16：不留透明邊，描邊同樣 1 px。
- 剪影要能分：四枚王印共用同一個造型（同一家族）：**正面平視的方形印牌，上緣一個小圓環**，看不到頂面或側面，不畫成立體方塊、寶箱，也不要像臉；靠印面紋樣分（山、劍與火、雷、漩渦），轉灰階後四枚還要分得出來。
- 顏色：王印是追逐物，可以有顏色：印身用中性銅色（`--border`、`--border-mid`、`--border-cap`），發光的印面用 `--rar-chase`／`--rar-chase-hi`，每枚另有一個紋樣色（見提示詞檔）。C* > 40 的像素 ≤ 不透明像素的 35%。
- 沒拿到時：同一張圖，程式轉單色 `--tx-dim` 剪影（M2-37），不另外畫。
- 出現的地方：追逐物品收集格 32、追逐橫幅 32（兩種尺寸）、物品說明那一行 16（取代 ◆，M2-29）。

### 5.2 SVG 導覽圖示（程式畫）
- 24×24 格（`viewBox="0 0 24 24"`），顯示 24 CSS px（直立 `#pnav`，現在是 22，改 24）；桌機 dock 也是 24。
- 線寬 2，端點與轉角用方的（`stroke-linecap: square`、`stroke-linejoin: miter`），水平垂直線的座標落在整數，斜線用 45°；不填色、不用漸層。
- 顏色跟字：一般 `--tx-dim`，選中 `--sel-ink`（在 `--sel` 上）。導覽圖示不准用飽和色。
- 營地的新圖示、鍛造的 hammer 在 M2-33 第 1 批一起畫。
- **390 戰鬥分頁已改（UIUX 11/20 17:06）**：390 底部 7 分頁的圖示不用本節 24 px SVG，改用 battle-hud v1.3 的 16×16 PNG 單色遮罩（＋`@2x` 32，程式染 `--tx-strong`／`--tx-dim`，見 `battle-hud/assets-borrowed.md` #2）；1280 分頁只有字＋鍵帽，不用圖示。其他導覽圖示仍照本節。

## 6. 特效
- 顏色只能用：元素 `--el-phys／-fire／-cold／-light／-chaos`、`--glint`、`--warm-glint-rgb`、`--fx-*`（只限特效）、掉落光用 `--rar-*`、昇華用 `--asc`／`--asc-hi`、追逐用 `--rar-chase`／`--rar-chase-hi`。不准用 `--bad`（那是負向數值）、不准用 `--act`。
- 疊法：核心 `--glint`，本體用元素色，外圈用元素色加 alpha；光用 `lighter`。不描邊、不加黑影。
- **飽和面積上限**（C* > 40 的像素，用該尺寸的整個畫面算）：
  - 一般打擊、元素命中：每個特效最大那一幀 ≤ 2%。
  - 招牌特效：最大那一幀 ≤ 12%，超過 8% 的時間 ≤ 0.4 秒。
  - 戰鬥中任意 5 秒平均 ≤ 15%（閒置狀態照 (c) ≤ 10%，特效不算在閒置裡）。
- 特效畫在跳數字之前（render.js 已是 `drawFx()` 再畫數字），跳數字永遠在最上面。
- 掉寶光柱：一張白色灰階的光柱，由程式依稀有度上色（`--rar-rare`、`--rar-unique`、`--rar-chase`），保證顏色跟 token 完全一樣。
- 兩種尺寸：特效在世界座標，跟著 ZOOM；直立 0.81 倍時，招牌特效的最小可見元素（火星、碎片）≥ 2 材質像素。

## 7. 跳數字
- 字：`700` Noto Sans TC，字級照 render.js 的表（不改），5 色照色票檔（`--dmg-hit／-crit／-hurt／-gain／-minor`）。
- 先描邊再填色：描邊 `--dmg-outline`，`lineWidth` 4（hurt 5），`lineJoin = 'round'`；描邊的淡出照色票檔修正 2。
- 不加光暈、漸層、斜體、陰影偏移；暴擊只靠字級和 pop。
- 字級是世界 px，會乘 ZOOM：直立 390 時 miss 14 → 11.4 CSS px、375 時 10.9。M2-33 第 3 批要加下限：螢幕上 ≥ 11 CSS px（dot 例外，≥ 9）。

## 8. 檢查
- 每批素材收進來先過提示詞檔 §6 的素材檢查（色票偏移、像素格、雜色反鋸齒、亮度、接縫）。
- 換進遊戲後，截圖照色票檔的「舒服」量測 (a)–(g)，用 `tools/comfort.py` 算（樣張要求不變，見 `specs/M2-36-palette-tokens.md`「樣張」一節）。地磚的亮度規則對應 (b)、(d)；飽和面積對應 (c)；框與 scrim 對應 (a)。

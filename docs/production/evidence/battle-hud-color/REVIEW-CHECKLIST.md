# 戰鬥 HUD 顏色驗收清單（第 6 步）

> 只列「比什麼、怎樣算過」。驗收由工程師的雲端工作階段疊截圖執行，判定人 UIUX設計師。
> 依據：`docs/production/specs/battle-hud/battle-hud-color-table.md`（第 2 步總表，以下稱「總表」）、`specs/battle-hud/battle-hud.md` v1.3.6（含 -4 §12–13、-5 §17–19、-6 §23、§28–29）、`S/M2-36-palette-tokens.md`。基準 main `53e1bbad`；驗收時寫上實際受驗的 commit。

## 0. 規則
- 尺寸：**1280×720，DPR 1**（必要時加 DPR 2 對 `@2x`）。390×844 只跑 `node tools/touch_check.js` 要全部 ✅，不驗顏色。
- 量法：CSS 元件用 computed style；canvas 用截圖取樣（取色塊中心 3×3 中位數，避開反鋸齒邊）。對比用 WCAG 2.x 相對亮度；色差用 CIEDE2000；色盲用 Machado 2009（紅、綠、藍黃）。
- 一項不符就是退回，不准「先 merge 再修」（battle-hud-4 §13）。總表已沒有待定列（UIUX 裁定 11/26）。
- 門檻：
  - 字：一般字 ≥ 4.5:1；大字（≥ 24 px，或 ≥ 18.66 px 粗體）與圖示、框、條 ≥ 3:1。
  - canvas 上的字有 2 px #000 描邊時，**字對描邊 ≥ 4.5，描邊對周圍場景 ≥ 3**（兩個都要過）。
  - 色值：CSS computed 跟總表新值**完全一樣**；canvas 取樣跟新值 ΔE2000 ≤ 2（有 α 的照 α 疊在取樣底上算預期值）。

## 3. 總表逐列
- 總表 §2（第 3 步）每列、§3.1（第 4 步）每列、§3.2 每項：到列出的「使用處」對應畫面取樣，**實際值＝總表新值**（CSS 完全一樣；canvas ΔE ≤ 2）。id 用總表的 token 名或列號，例如 `T3--dmg-crit`、`T4-44`、`T4-159-6`。
- 每列另驗：字類 ≥ 4.5、圖示／環／點 ≥ 3（對實際底色）；敵方用的環與點黑邊不透明，我方的是 9%。
- 範圍外（總表 §5）不驗。
- 程式靜態檢查：`git grep` 沒有新的寫死色值；`-rgb` 是逗號格式；半透明寫 `rgba(var(--x-rgb), α)`；M2-36 驗收腳本跑過。

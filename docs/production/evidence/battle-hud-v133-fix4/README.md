## 390 偶發（點鞋子欄開到腰帶）

- **原因**：tapIn 量中心點時，角色面板的 `top` 轉場還在滑。390 開全版面板時 `#pinv` top 434 → 24（`body.touch.port .panel { transition: top 220ms }`），鞋子欄 y 676 → 266；腰帶就在鞋子正下方（鞋子 10,266,56×56、腰帶 10,328,56×56）。量到的中心比停好時低 ≥34 px，手指放開時（觸控合成的 click 在放開那一刻才判定目標）底下已經是腰帶 → 「腰帶空的」，連帶「說明框…鞋子現在空著」「按裝備：換進選的那一格」兩項失敗。
- **跟本 PR 的關係**：本 PR 的半版面板上緣是 434（main 388，HUD 多佔 46 px），所以開全版要滑 410 px（main 364 px），一樣 220 ms；正常時轉場在開面板後約 255–280 ms 停（main 約 260 ms），tapIn 在約 320–330 ms 量位置，只差 50–70 ms。機器一忙、開面板後第一格晚畫，轉場晚起跑就會量到滑到一半的位置。main 上同樣的餘裕略大、滑的距離略短，所以比較難碰到。
- **重現**（`logs/flake_probe.py` 把 touch_check 這一段加上逐格紀錄，並在開面板後第一格故意卡住 N ms 模擬機器忙）：修前卡 280 ms → 手指在 y 330，開到「腰帶空的」，三項 ❌；修後卡 0／280／300 ms 都點到鞋子、三項 ✅（`logs/flake_repro.log`）。
- **修法**（tools/touch_check.js，tapIn）：量中心點前先等「目標所在元素（含祖先）上有限長度的動畫／轉場」跑完再 scrollIntoView、量位置。斷言、等待時間、點的位置規則都沒改。遊戲程式沒改：玩家在面板滑動中點下去，瀏覽器本來就是放開時才決定點到誰。
- **390×844 連跑 10 次**：見下「測試」。

## F2 原因與證明（`tools/bh_f2.js` → `f2_proof.json`、`logs/bh_f2.log`）

同一頁、同一流程（生命 1000 → 300，最大 1000），三種做法：

| 做法 | --v | 300 ms 後填滿寬 | 應為 round(0.3×內寬) | 轉場狀態 |
|---|---|---|---|---|
| A 不凍結時鐘（真時間） | 0.300 | 390：102.59；1280：134.39 | 103；134 | 已結束，`transitionend` 有觸發 |
| B fix2 的擷取順序（`hudTick()` 後同一段 JS 立刻 `DBG.freeze()`） | 0.300 | 390：**342**；1280：**448**（全滿） | 103；134 | `width` 轉場 **paused、currentTime 0** |
| C 本輪（`DBG.settle()`） | 0.300 | 102.59；134.39 | 103；134 | 已結束 |

- `setV('bhpv')` 有更新（三種都是 --v 0.300，字也是「生命 300 / 1000」），不凍結時寬度正確 → **不是程式 bug**。
- `DBG.freeze()` 會 `pause()` 所有動畫；剛建立的 `width 120ms` 轉場被停在第 0 毫秒，畫面停在舊值（滿血）。
- 26 張重拍的填滿寬度（`chk` 的 F2 列，`|寬 − round(值÷最大×內寬)| ≤ 2`）：例 lowhp 43/140 → 104.98／105（390，填到 x116）、137.53／138（1280）；es_full 820/1000 → 280.44／280、367.36／367；lowlife 300/1000 → 102.59／103；low2 150/1000 → 51.3／51；能量護盾 es_partial 240/600 → 136.8／137、179.19／179；lowcomb 30/600 → 17.09／17。全部 40 張都過。
- check.js 新增：真時間等 `transitionend` 後量寬度、`DBG.settle` 擷取量寬度，兩尺寸。

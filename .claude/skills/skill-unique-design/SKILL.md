## 兩種草案共用的規則

1. **爽**：遊戲主打刷的爽、打得爽，這是跟 PoE 的差別。特色要在畫面上看得到。
2. **掛機**：角色由 AI 打。設計時先想「AI 會怎麼用」，不要設計要玩家抓時機的東西。
3. **用現有名詞**：先查 `js/data.js` 的 `TERMS`（名詞定義）與 `docs/名詞表.md`。遊戲裡已經有定義、但沒有來源的名詞優先用。文字照 `docs/文字規範.md`：「增加 X%」（同池相加）、「X%更多」（相乘）、「+X」、「將 X% 的物理傷害轉換為…」。
4. **不跟昇華、天賦樹重複**：動手前跑 `node .claude/skills/skill-unique-design/draft_check.js --taken`，把昇華大點、基石、天賦大點的效果看過一輪。撞到就換。
5. **平衡先不管**，數字都是暫定；但要寫數字，不要留空。
6. **已經拿掉或藏起來的不要用**：護符（拔掉）、鏈錘（拔掉）、魔符（隱藏）、光環第五批（取消）。
7. 新東西要補底層規則的標 ⚠️，並在檔尾的表寫「缺什麼、最接近的現有做法」。底層規則在 `docs/企劃書.md` 7.2、7.3。
8. 每輪做完：更新 `docs/INDEX.md` 對應列（狀態一律「草稿，不可交辦」）、在 `docs/production/CHANGELOG.md` 最上面記一行（引用使用者原話）。push 前先問使用者。

## 設計技能

### 一把武器的組成

AI 照技能欄順序，冷卻好就放，都放不出來才用左鍵那招（`js/ai.js` 的 `aiOrder`）。技能欄只有 5 格，一把武器 7 招以上讓玩家挑。

| 角色 | 幾招 | 冷卻 |
| --- | --- | --- |
| 普攻 | 2 | 沒有冷卻，放左鍵；一招打單體、一招打範圍或打遠 |
| 位移 | 1 | 3～5 秒 |
| 收割／花資源 | 1～2 | 3～5 秒，剛好夠攢資源 |
| 主力 | 1～2 | 6～10 秒 |
| 大絕或增益 | 1 | 12～20 秒，畫面最大的一招 |

- 除了普攻，每招都要有冷卻、次數或彈匣，不然 AI 會一直放同一招。同一把武器的冷卻要錯開。
- 十字弓、陷阱、地雷整組都是彈匣或次數制、沒有普攻，使用者 2026-11-27 說沒關係（`sim_rotation.js` 會提醒，這三組可以不理）。
- 每把武器先寫一句定位（靠什麼資源、怎麼打），再寫招。不一定每招都要有連動，但每招要有一句說得出來的特色。
- 資源（能量球、盛怒、連擊、灌注、屍體）的來源可以是武器自己的招，也可以是通用技能（戰吼、印記）。印記是通用的。
- 可以改舊招，每招標「新／改／不動」，改的寫一句理由。

### 格式

每把武器先一張表（招｜狀態｜角色｜冷卻），下面只寫新招與有改的招：

```
【名字】（新）
  標籤：攻擊、近戰、打擊、冷卻｜魔力 待定｜冷卻 6 秒
  說明：一到兩句，開頭用動詞，幾乎不放數字。
  ・一行一個數字或一條規則
  特色：這招跟同武器其他招不一樣的地方。
```

### 模擬

```bash
node .claude/skills/skill-unique-design/sim_rotation.js
```

照 AI 的規則粗估每把武器 60 秒內各招放幾次（每把取第一招普攻＋冷卻最長的 4 招）。看三件事：普攻佔比在 15～80% 之間、沒有一招冷卻招佔超過一半、每把都有普攻。它不算資源與條件，是上限；要準的數字等招進了遊戲跑 `tools/dmg_check.js`。

## 設計傳奇

### 一件傳奇的組成

```
【名字】基底｜物品等級 N+｜來源（專屬才寫）
  詞綴：增加 66～114% 物理傷害；增加 12～20% 攻擊速度；力量 +15～23
  ★ 特色詞；其他不在詞綴池裡的固定詞 ——一句說明。⚠️
```

1. **基底**：用遊戲裡現有的基底名。基底決定部位、最低物品等級與能出哪些詞綴。
2. **詞綴**（使用者 11-27：「傳奇物品都要塞一些詞綴屬性」）：從這個部位的詞綴池挑，寫法跟稀有裝的詞綴一模一樣。詞綴池＝遊戲現有的 39 條＋`詞綴池擴充草案.md` 的新單項與複合詞綴（使用者 11-27：「拓寬詞綴池…複合詞綴一起補入」）；`--aff` 印出來的就是合起來的池，標「新」「複合」的是草案裡的；SU-02 起先讀程式的 `AFF`（草案已做進遊戲的就照程式），程式還沒有的列另標「草案、程式還沒有」（目前 `meleeRange`、`selfAilDur`）。
   - 複合詞綴一條給兩種能力，寫成「護甲 +80～120、最大生命 +30～45」，算一條。
   - 傳奇不能鍛造，只能腐化（使用者 11-27）；所以詞綴的數值只能靠掉落的範圍去刷。
   - 查詞綴池與建議範圍：`node .claude/skills/skill-unique-design/draft_check.js --aff <基底名> [物品等級]`。長杖、法杖、權杖、陷阱器用的是法系詞綴池（法術傷害、精魂、能量護盾、範圍效果等），跟其他武器不同。
   - 原本意思跟池裡某一條相同的普通詞，改寫成池的寫法放進詞綴行；池裡沒有的（例如「增加 X% 護甲」，池裡只有「護甲 +N」）留在第二行、放在 ★ 前面。
   - 條數下限：物品等級 1～35 兩條、36～71 三條、72～89 四條、90 以上五條。
   - 至少一條是範圍詞（a～b）；想固定的寫單一數字。使用者：「有些詞綴可以固定，有些詞綴是範圍，這樣才不會刷到就畢業」。
   - 挑跟這件的打法有關的：近戰武器給物理與攻速，法系給法術傷害與能量護盾，坦的給生命與抗性。不要每件都塞同樣三條。
   - 同一條詞綴不重複；範圍不要超過那條詞綴整條上限的 1.25 倍。
3. **特色詞**（★）：改規則的那一條，戴上去打法就變了。通用 1 條；Uber 專屬 2 條。
4. **物品等級**：照 1～100。最低物品等級＝基底等級 ×6（基底等級 1 的寫 1）；賽制菁英王專屬至少 60、終局王專屬至少 80、Uber 至少 90（主幹王的專屬照基底）。專屬查詞綴範圍時要把物品等級帶進去：`--aff <基底名> 60`。程式現在還是 1～16，基底等級改成 1～100 之後 `draft_check.js` 的 `minLv` 要跟著改。

### 通用與專屬

- **通用**：任何地方都會掉。要有一批物品等級 1 就會掉的。
- **專屬**：只有對應的王掉，效果比通用特殊，讓人願意去刷。三層，越難越特殊：

| 層 | 誰 | 強度 |
| --- | --- | --- |
| 菁英王 | 十二生肖、牛頭馬面黑白無常、刑天風伯雨師、七情、四凶；主幹王 | 一條別處沒有的特色 |
| 終局王 | 太歲、閻羅、蚩尤、三尸、燭龍 | 能當一套打法的核心 |
| Uber | 太歲星君、十殿閻羅、涿鹿兵主、三彭、燭九陰 | 兩條特色詞，最強；可以把同系列串起來 |

- 名字跟世界觀走（`docs/世界觀.md`），專屬的效果要呼應那隻王。
- 十二生肖的效果要避開神裔昇華（也就是神格）裡那十二位神的效果。
- 傳奇珠寶照每個賽制已經定的珠寶種類做（`docs/production/adjust/天賦樹與珠寶孔.md`）。

### 檢查

```bash
node .claude/skills/skill-unique-design/draft_check.js
```

每件檢查：基底存在、名字不重複、有物品等級且不低於基底、有「詞綴：」行、每條詞綴是這個部位詞綴池（含擴充草案）裡的寫法、條數夠、有範圍詞、有 ★、沒提到護符。有 ❌ 不交差。它不檢查特色詞有沒有重複，那要自己對 `--taken`。

## 交付時要講的

件數與檢查結果、標 ⚠️ 的有幾件、哪些是還沒對過程式的（特色詞通常都沒對過）、要使用者決定的題目。

## 用的數字與出處
- **樹中心**＝原點 (0, 0)：`tools/tree_bake.js` 的 `pol = (deg, r) => ({ x: Math.sin(deg * RAD) * r, y: -Math.cos(deg * RAD) * r })`（ptreeGen2 裡，所有幹道點都由它從原點放出去）；`js/tree.js` 第 297 行 `treeR` 也是 `Math.hypot(n.x, n.y)`（以原點算半徑）。
- **最小點距**：兩個都量了。
  - 現有點兩兩最近距離的實際下限：**40.644**（c343_0–c343_1，同一叢集的兩個小點；第 1 百分位 47.7、中位數 83.8）。
  - tree_bake 的門檻：審核「兩點太近」＝ `NR(a)+NR(b)+8`（小點 10、大點 19、起點 20、基石 30 → 小點對小點 28）；生成時的 `free()` 不同叢集之間要再隔 52（小點對小點 72）。
  - **用 40.644**：任務舉例就是它；而且 tree_bake 的兩個門檻都要先知道孔畫多大（`NR`），孔現在沒有半徑，用它就等於自己定孔的大小。40.644 比審核門檻 28 嚴，也是現有樹上每一對點都做得到的值。
- **偏移**：從掛點沿半徑往外，取「跟每個既有點（N）與先放好的孔距離都 ≥ 40.644」的最大偏移。照字面，整條射線上可行的範圍一直延伸到樹外（無限大），所以取**從掛點往外第一段可行範圍的盡頭**（往外推到碰到下一個點為止）。17 孔都被點擋住；**J3c 沒有點擋住**，上限用 `tools/tree_bake.js` 的 `rim`（叢集點放不出去的半徑上限：`fit()` 裡 `r > rim(x, y)` 就不放；這次把它提成檔案層級的 `pt2Rim`，計算式不變、樹烘出來位元組相同）。取到 0.1 後再驗一次，不夠就往內退 0.1。
- **壓線門檻**：tree_bake 的「線壓到點」＝點到線 < `NR+6`；孔用最小的半徑 10 → **16**（最寬鬆；用任何更大的半徑，壓線的只會更多）。現有點到別人線的實際最近距離是 35.5（c468_1 ↔ t94-c468_0），僅供參考。
